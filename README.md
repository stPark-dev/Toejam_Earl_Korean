  <img src="홀이와뚱이.png" alt="토잼 & 얼 한국 정발판 패키지" width="480">

**현재 버전: v0.6.0 (공개 시험판)**

메가드라이브용 **ToeJam & Earl (U) REV00** 을 한글로 옮긴 패치입니다.
1991년 세가와 Johnson Voorsanger Productions가 만든 이 게임은 펑코트론 행성에서 온 두 외계인,
토잼과 얼이 추락한 지구에서 로켓선 부품 10개를 찾아 모으는 액션 게임입니다.

게임에 나오는 글자를 그냥 바꿔 끼운 게 아니라, 원작의 글자 출력 코드 자체를 한글을 그릴 수 있는
새 68000 코드로 갈아 끼웠습니다. 인트로·대사·메뉴·HUD가 모두 한글 글꼴로 나옵니다.

## 이름에 대하여

이 게임은 예전에 국내에 **「홀이와 뚱이」** 라는 이름으로 정식 발매되었습니다.
빨갛고 홀쭉한 토잼이 "홀이", 주황색에 몸집이 큰 얼이 "뚱이"였던 셈입니다.
그때를 기억하는 분들께는 정겨운 이름이지만, 이 한글화에서는 원문의 랩·펑크 분위기와
캐릭터 이름을 살리기 위해 **토잼 & 얼**로 옮겼습니다. 위 패키지 이미지에도 보이듯
토잼 & 얼 표기 역시 국내에 소개된 적이 있어 낯설지는 않을 겁니다.

## 설치 방법

ROM은 배포하지 않습니다. 직접 가지고 계신 카트리지에서 뽑은 원본 ROM에 **IPS 패치**를 씌우세요.

### 1. 원본 ROM 준비

| | |
|---|---|
| 파일 | `Toejam & Earl (U) (REV00) [!].gen` (또는 `.bin`, `.md`) |
| 크기 | 1,048,576 바이트 (1MB) |
| MD5 | `0a6af20d9c5b3ec4e23c683f083b92cd` |

MD5가 다르면 패치가 제대로 먹지 않습니다. 확인 방법:

```bash
md5sum "Toejam & Earl (U) (REV00) [!].gen"                   # Linux / macOS / Git Bash
certutil -hashfile "Toejam & Earl (U) (REV00) [!].gen" MD5   # Windows
```

**`.smd` 파일을 가지고 계신 경우**: 그대로는 안 됩니다. `.smd`는 인터리브 형식에 512바이트
헤더가 붙어 있어 먼저 `.gen`으로 풀어야 합니다. 헤더를 버리고, 16KB 블록마다 앞 8KB가 홀수
번째 바이트, 뒤 8KB가 짝수 번째 바이트가 되도록 합치면 됩니다.

<details>
<summary>.smd → .gen 변환 스크립트 (파이썬)</summary>

```python
import sys
data = open(sys.argv[1], 'rb').read()[512:]        # 512바이트 헤더 버리기
out = bytearray()
for i in range(0, len(data), 16384):
    blk = data[i:i + 16384]
    odd, even = blk[:8192], blk[8192:]
    for a, b in zip(even, odd):
        out += bytes((a, b))
open(sys.argv[2], 'wb').write(bytes(out))
```

</details>

### 2. 패치 적용

릴리스에서 `tje_ko.ips`를 받아 아래 도구 중 하나로 씌웁니다.

- [Floating IPS (Flips)](https://www.smwcentral.net/?p=section&a=details&id=11474) — Windows/Linux, 가장 무난합니다
- [Lunar IPS](https://fusoya.eludevisibility.org/lips/) — Windows
- [ROM Patcher JS](https://www.marcrobledo.com/RomPatcher.js/) — 웹브라우저에서 바로, 설치 불필요

패치를 씌우면 ROM이 **2MB로 커집니다**. 정상입니다 (한글 글꼴과 새 코드가 들어갈 자리).

| | |
|---|---|
| 결과 크기 | 2,097,152 바이트 (2MB) |
| 결과 MD5 (v0.6.0) | `eef171cb4c7e68359416d33fc16884f2` |

### 3. 실행

- **에뮬레이터**: [BlastEm](https://www.retrodev.com/blastem/)(정확도 높음), RetroArch + Genesis Plus GX,
  Kega Fusion 등 아무거나 됩니다.
- **실기**: Mega EverDrive 같은 플래시 카트리지에 넣으면 됩니다. 다만 아직 실기에서 전 구간을
  확인하지 못했습니다 (아래 [알려진 문제](#알려진-문제) 참고).

### 조작

기본 배치 기준입니다. 게임 안 `컨트롤러 설정`에서 바꿀 수 있습니다.

| 버튼 | 기능 |
|------|------|
| 방향키 | 이동 |
| A | 행동 (선물 열기) |
| B | 선물 목록 |
| C | 지도 |
| START | 메뉴 / 결정 |

> **선물은 A만 눌러서는 열리지 않습니다.** B로 선물 목록을 띄우고 방향키로 고른 뒤 A를 눌러야 열립니다.

## 알려진 문제

- **실기 검증을 하지 못했습니다.** 에뮬레이터(Genesis Plus GX)로만 확인했습니다. 실기에서 문제가
  보이면 제보해 주세요.
- **레벨 시작 메시지**("이 층에 로켓 부품이 있다" 등)를 화면으로 못 봤습니다. 엘리베이터를 타야
  나오는데 자동 입력으로 36만 프레임을 돌려도 엘리베이터에 닿지 못했습니다. 게임 오버·로켓 상태
  화면과 같은 출력 경로를 쓰므로 위험은 낮다고 봅니다.
- **크레딧**도 화면으로 못 봤습니다. 게임을 끝까지 깨야 나옵니다.
- 원작에 없던 글자를 넣은 만큼 VRAM 사용이 늘었습니다. v0.4.2에서 인트로 배경이 깨지던 문제를
  고쳤지만, 비슷한 증상이 보이면 어느 장면인지 알려주시면 도움이 됩니다.

### 검증 상태

`tools/emu/harness.py`로 인트로 → 캐릭터 선택 → 메뉴 → 잼 아웃 → 컨트롤러 설정 → 게임 플레이 →
지도 → 선물 목록 → 로켓 상태 → 말풍선 → 게임 오버까지 화면으로 확인했습니다. 깨짐이나 잘림은
없었고, 인트로는 원본 ROM과 같은 프레임을 찍어 배치까지 대조했습니다(짧은 줄이 왼쪽 위에 붙는 것도
원본과 같습니다).

코드 사이에 한두 개씩 박혀 있던 말풍선은 `TEXT_WINDOWS` 바깥이라 추출조차 되지 않아 계속 영어로
나왔습니다(`I'm stuffed`, `yummm`, `Youch!`, `Bye Toejam` 등). pcrel·abs32 참조 대상 주소마다
그 자리에 NUL로 끝나는 ASCII가 있는지 훑어 16개를 찾았고, 포인터 표로만 걸려 있던 두 번째 등급
이름표(0xA9FEC)에서 8개를 더 찾았습니다. 같은 검사를 `tests/test_build.py`가 지킵니다.

## 기술 개요

- 게임 텍스트는 세 가지 경로로 출력됩니다. 스프라이트 스트립(인트로, 아이템), 말풍선(대사),
  배경 플레인(메뉴, HUD, 메시지). 세 경로의 글리프 렌더러를 모두 새 68000 코드로 교체했습니다
  (`tools/tje/asm/text.s`, ROM 확장 영역 0x100000에 배치).
- 한글은 16x16(Galmuri14), 영문은 8x16(Galmuri11) 글리프입니다.
  [Galmuri](https://github.com/quiple/galmuri)(SIL OFL) 폰트 획을 2px로 굵히고 글자마다 위아래로 1px씩
  어긋나게 해 원작의 손글씨 느낌을 냈습니다. 스프라이트 텍스트는 검은 글자·흰 외곽선, 메뉴·메시지는
  원작 메뉴 폰트의 노란 글자·갈색 그림자·검은 상자 팔레트를 씁니다.
- 한글 한 글자는 2바이트 코드(리드 `0x80|hi`, 트레일 `1..255`)로 저장되며, 번역에 실제로 쓰인
  음절만 글리프 테이블에 들어갑니다.
- 게임 그래픽은 `[타일 수][4bpp 타일…]` 형식의 비압축 에셋입니다. 그림으로 들어간 글자는
  `tools/tje/labels.py`에 (에셋, 타일 번호, 한글, 팔레트)로 정의해 새 타일로 덮어씁니다.
- ROM은 1MB에서 2MB로 확장되고 헤더 체크섬을 다시 계산합니다.

### HUD 8x8 한글에 대하여

하단 HUD는 8픽셀 3줄짜리 패널이어서 16픽셀 한글이 들어가지 않습니다. 이 영역은 Galmuri7 기반 8x8 한글을
한 줄로 출력합니다. 이때 글꼴을 7px이 아니라 **8px로 렌더**해야 합니다. Galmuri7의 한글은 8단위 격자에
그려져 있어서 7px로 요청하면 받침 있는 글자가 전부 뭉개집니다(v0.4.3까지 "휴가"가 "호기"처럼 보이던 원인).
8px로 그리면 글자가 타일의 1~7행을 채워 잘리지 않고 밑줄도 고르게 맞습니다.

글리프 타일은 게임이 스프라이트 그래픽에 쓰는 스테이징 버퍼와 VBlank DMA 큐로 올리고,
VRAM 0xC000~0xCFFF(모든 장면에서 네임 테이블도 스프라이트 풀도 아닌 영역)에 둡니다.
`tools/tje/build.py`의 `HUD_KOREAN`을 `False`로 두면 원본 영어 HUD로 빌드됩니다.

## 빌드

원본 ROM은 저장소에 포함하지 않습니다. `Toejam & Earl (U) (REV00) [!].gen`
(MD5 `0a6af20d9c5b3ec4e23c683f083b92cd`)을 저장소 루트에 두세요.
`.gitignore`가 `*.gen`, `*.smd`를 막고 있어 실수로 올라가지 않습니다.

```bash
python3 -m venv venv && venv/bin/pip install pillow capstone pytest
# m68k 어셈블러: apt install binutils-m68k-linux-gnu
venv/bin/python -m tools.tje.build        # -> build/tje_ko.gen
venv/bin/python -m tools.tje.patch        # -> build/tje_ko.ips (배포용)
venv/bin/python -m pytest tests
```

`tools/tje/patch.py`는 만든 패치를 그 자리에서 되적용해 빌드한 ROM이 그대로 나오는지 확인한 뒤에만
파일을 씁니다.

<details>
<summary>Windows에서 빌드하기 (WSL)</summary>

Windows에는 m68k 툴체인이 없으므로 WSL(Ubuntu)에서 빌드합니다. sudo를 쓸 수 없는 환경이라면
`binutils-m68k-linux-gnu` .deb를 받아 `dpkg -x ~/tje/m68k`로 풀고 아래를 지정하면 됩니다.

```bash
export M68K_BIN=$HOME/tje/m68k/usr/bin/
export LD_LIBRARY_PATH=$HOME/tje/m68k/usr/lib/x86_64-linux-gnu
```

파이썬 쪽은 `python3 -m venv --without-pip`으로 만든 venv에 `get-pip.py`를 돌려
Pillow·capstone·pytest를 넣습니다. 저장소는 `/mnt/c/...` 경로로 그대로 접근하면 됩니다.

</details>

`translations/strings.csv`의 `ko` 열을 고치고 다시 빌드하면 반영됩니다.

- 말풍선 대사: 최대 12열(한글 6자)
- 선물 이름: 최대 13열
- 그 외: 최대 32열(한글 16자)
- 한글은 2열, 영문·숫자·기호는 1열로 계산합니다. 초과하면 빌드가 실패하며 해당 줄을 알려줍니다.

원문 자리에 안 들어가는 번역은 ROM 확장 영역으로 옮기고 참조하는 코드를 고쳐 씁니다.
`pea (d16,pc)` 참조는 뒤에 `nop`이 있어야 `pea abs.l`로 늘릴 수 있습니다.

## 검증

`tools/emu/harness.py`는 Genesis Plus GX libretro 코어를 파이썬에서 직접 구동해 헤드리스로
스크린샷·RAM 상태를 뽑습니다. 코어 파일 `tools/emu/genesis_plus_gx_libretro.so`는
[libretro buildbot](https://buildbot.libretro.com/nightly/linux/x86_64/latest/)에서 받아 넣으세요.

```bash
venv/bin/python tools/emu/harness.py build/tje_ko.gen \
    --frames 1800 --press 900:start --shot 1800:intro.png
```

게임 화면까지 몰고 가는 입력 순서는 `900:start` → `2400:start` → `2760:down` → `2820:start`
→ `4700:start` 입니다 (약 4900프레임부터 게임 플레이).

## 제보
